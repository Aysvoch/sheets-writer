# Vacancy Pipeline

Автоматический поиск junior/стажёрских вакансий в продакт-менеджменте: сбор с источников каждые 12 часов без участия человека, оценка релевантности через LLM, чистый лист в Google Sheets и уведомление в телеграм.

Живой продукт: работает в облаке с августа 2026, присылает новые подходящие вакансии дважды в сутки.

## Проблема

Искать первую роль в продукте вручную - это каждый день открывать десяток телеграм-каналов и HH, листать поток, где 90% - не твоё: Senior-позиции, не-продакт, реклама курсов. На практике так делать перестаёшь через неделю.

- **Где вообще искать?** hh.ru закрыл публичный API для соискателей (на форме регистрации приложения указано: «поддержка API для соискателей прекращена 15 декабря 2025»; фактически публичный доступ отвалился с апреля 2026). Открытый канал остаётся - это агрегаторы в телеграме и career-площадки.
- **Как отделить своё от чужого?** junior-соискателю не нужны Middle/Senior/Project Manager, но в потоке они вперемешку, и глазами это фильтровать долго.
- **Как не смотреть одно и то же дважды?** каналы репостят друг друга, одна вакансия приходит из пяти мест.

## Решение

Пайплайн: источники → Python → LLM-оценка → Google Sheets → телеграм. Запуск по расписанию через GitHub Actions (дважды в сутки, не зависит от включённого компьютера).

```
Источники
  ├── Хабр Карьера (парсинг HTML)
  └── 34 телеграм-канала (t.me/s/, публичный веб-доступ)
        │
        v
vacancy_collector.py ── предфильтр по продуктовым словам
  │                     дедуп по source_id, отсечка старше 10 дней
  v
llm_scorer.py ──────── LLM (OpenRouter) оценивает 0-10 + вердикт
  │                     отсечка score < 3, сортировка по оценке
  v
Google Sheets ──────── лист "Вакансии": оценка, вердикт, ссылка, чекбокс
  │
  v
Telegram ───────────── "🔔 Новых вакансий: N"

run_all.py ─────────── оркестратор: сбор → оценка (если сбор успешен)
GitHub Actions ─────── cron 06:00/18:00, секреты в GitHub Secrets
```

## Ключевые механики

**Оценка релевантности под профиль, а не поиск по ключевым словам.** LLM получает текст вакансии и профиль кандидата (junior/стажёр, переход в продукт) и ставит оценку 0-10 с коротким вердиктом «почему». Поиск по словам «product manager» вернул бы и Senior, и Project Manager - модель же понимает, что Senior-позиция для junior не подходит, и ставит ей низкую оценку с объяснением.

**Отсечка на входе, а не фильтр на выходе.** В лист пишутся только вакансии с оценкой ≥3 - остальное не засоряет таблицу. Порог выбран по данным: на потоке видно, что оценки 0-2 стабильно оказываются не-продакт или явный Senior, а с 3 начинается «есть нюанс, но глянуть можно».

**Дедуп по источнику, устойчивый к репостам.** У каждой вакансии есть `source_id` (канал + id поста). Каналы репостят друг друга, но пост со своим id уникален - повтор не запишется. `source_id` живёт в скрытой технической колонке, дедуп читает её, пользователь не видит.

**Устойчивость LLM-вызова.** Дешёвая модель нестабильно держит формат ответа: игнорирует запрос «не размышляй» и вставляет рассуждения вместо JSON. Лечится не повторами (при temperature=0 повтор даёт тот же сбой), а параметром `reasoning: exclude` - модель думает молча и возвращает только результат. Сетевые сбои (таймаут, 429) - отдельно, их вытягивает ретрай с паузой.

**Самоочистка листа.** Строки старше 10 дней удаляются каждый прогон (вакансия протухла), плюс страховочный потолок. Жёсткого лимита по количеству нет намеренно - он породил бы карусель: удалённая свежая вакансия вернулась бы из сырья как «новая». Разгрузка только по возрасту, который отсекается и на входе.

## Почему LLM, а не правила

Можно было фильтровать регулярками по словам - дёшево и без внешних вызовов. Но релевантность junior-вакансии не выражается списком слов: «Product Manager, 1-3 года опыта» формально подходит по названию, а по сути нет. Модель читает требования целиком и отвечает на вопрос «подходит ли это конкретному кандидату», а не «есть ли в тексте нужное слово». Цена - центы за прогон на дешёвой модели; на потоке в сотню вакансий это копейки.

Оценки проверены на данных: вакансии, которые модель забраковала низким баллом, при ручной сверке действительно оказывались не-junior (требуют опыт от 1-3 лет, Senior-грейд). Годное в отсечку не уходит.

## Продуктовые решения и trade-offs

| Решение | Альтернатива | Почему так |
|---|---|---|
| LLM-оценка релевантности | Фильтр по ключевым словам | Слова не отличают junior-вакансию от Senior с тем же названием |
| Отсечка score ≥3 на входе | Писать всё, фильтровать глазами | Инструмент, где 75% строк - шум, перестаёшь открывать |
| Google Sheets как интерфейс | БД + веб-UI | Ноль порога: открыл ссылку, чекбоксом отметил просмотренное |
| Дедуп по source_id | Дедуп по тексту/ссылке | id поста уникален и стабилен, текст репоста может отличаться |
| `reasoning: exclude` | Ретраить битый JSON | При temp=0 повтор даёт тот же сбой; проблема в формате, не в сети |
| Разгрузка по возрасту | Жёсткий лимит N строк | Лимит порождает карусель удаления-перезаписи через дедуп |
| Дешёвая модель | Топовая модель | На потоке в сотни вакансий разница в качестве не окупает цену |
