ЗВЕНО 1: сбор вакансий -> Google Sheets (без LLM)
=================================================
Источники: Хабр Карьера (сайт) + 22 телеграм-канала.
Выход: два листа сырья "Хабр" и "Телеграм". Фильтрации нет - её сделает LLM (звено 2).

ЗАПУСК ЛОКАЛЬНО
  1. pip install -r requirements.txt
  2. .env из .env.example (SPREADSHEET_ID, AUTHOR); рядом credentials.json.
  3. Таблицу расшарить на email сервис-аккаунта (Редактор).
  4. python vacancy_collector.py

ЧТО ДЕЛАЕТ
  - Хабр: запросы (product manager/owner/менеджер продукта/продакт/delivery/проджект)
    по Казань+Москва+удалёнка, все страницы. Поля: должность/компания/вилка/локация/
    грейд/рейтинг/дата/ссылка. БЕЗ отсева - тянет всё, что вернул поиск.
  - Телеграм: t.me/s/<канал>, сырой ТЕКСТ поста + ссылка (поля извлечёт LLM).
    Битые/приватные каналы помечаются в логе, прогон не падает.
  - Дедуп по source_id. Первый прогон глубокий (DEEP_FIRST_RUN=True).
  - Колонки llm_оценка/llm_вердикт/Комментарии заведены пустыми, звено 1 их НЕ трогает.

ДОБАВИТЬ ИСТОЧНИК (модульно)
  - Новый телеграм-канал: дописать хендл в список TG_CHANNELS. Всё.
  - Новый сайт: написать функцию feed_xxx() по образцу feed_habr(), вернуть список
    RawVacancy, вписать в реестр STRUCTURED_SOURCES. Ядро подхватит.

НАСТРОЙКИ (в начале файла)
  HABR_QUERIES, HABR_LOCATIONS, HABR_REMOTE, HABR_MAX_PAGES,
  TG_CHANNELS, DEEP_FIRST_RUN, TG_DEEP_PAGES, TG_SHALLOW_ONLY.
  После первого глубокого прогона можно поставить DEEP_FIRST_RUN=False
  (или TG_SHALLOW_ONLY=True) - дальше берётся только свежее.

ОГРАНИЧЕНИЯ (честно)
  - Парсер Хабра протестирован на реальном HTML (24/24 карточки, поля чистые).
  - Парсер телеграма написан по структуре t.me/s/ (проверял на живом канале),
    но полный прогон по всем каналам у меня прогнать нельзя - первый запуск твой.
  - Телеграм-каналы с неверным хендлом/приватные будут в логе как unavailable -
    поправь хендл или убери из списка.
  - Это ЗВЕНО 1. Фильтрации релевантности пока нет - в листах будет и мусор.
    Его уберёт LLM в звене 2 (оценка + вердикт в пустые колонки).

БЕЗОПАСНОСТЬ
  credentials.json и .env - только локально, в .gitignore. Перед push: git status.


ОБНОВЛЕНИЕ (предфильтр + чистка)
================================
- Предфильтр ВКЛЮЧЁН (режим cut): в таблицу пишутся только записи с продуктовым/
  менеджерским маркером (PRODUCT_KEYWORDS в начале файла - широкий список,
  можно расширять). Java/SRE/реклама и прочий мусор отсекаются ДО записи.
  Тонкий отбор под твой профиль сделает LLM (звено 2).
- Телеграм-текст чистится: срезается навигация канала (строки с │) и реклама
  (Софи и т.п.), длина ограничена TG_TEXT_MAXLEN. В таблицу идёт тело вакансии.
- Убраны нечитаемые чаты: rabotaICL, products_jobs (это группы, не каналы).

ВАЖНО ПЕРЕД ПОВТОРНЫМ ЗАПУСКОМ
=============================
Первый прогон уже залил в листы "Хабр" и "Телеграм" сырьё БЕЗ фильтра.
Дедуп по source_id не удаляет старое - он только не задваивает.
Чтобы получить чистые листы (только продуктовое), перед повторным запуском:
  - удали вкладки "Хабр" и "Телеграм" в таблице (правый клик по вкладке -> Удалить),
  - запусти скрипт снова: он пересоздаст листы и зальёт уже отфильтрованное.
