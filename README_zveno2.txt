ЗВЕНО 2: LLM-оценка -> лист "Вакансии" в "Таблице неудач"
=========================================================
Читает сырьё (Хабр/Телеграм) из файла-сборщика, по каждой НОВОЙ вакансии зовёт
LLM (через OpenRouter), извлекает поля + оценка 0-10 + сухой вердикт, пишет чистую
строку в лист "Вакансии" внутри "Таблицы неудач" (с подсветкой). Дедуп по source_id.

ПЕРЕД ЗАПУСКОМ
  1. .env должен содержать (уже добавлено):
       SPREADSHEET_ID          - файл-сборщик (сырьё)
       TRACKER_SPREADSHEET_ID  - "Таблица неудач"
       OPENROUTER_API_KEY      - ключ OpenRouter
     (TG_BOT_TOKEN/TG_CHAT_ID - опционально, для счётчика)
  2. "Таблица неудач" расшарена на сервис-аккаунт (Редактор). [сделано]
  3. Сначала запусти звено 1 (сбор сырья), потом это.
  4. python llm_scorer.py

ПЕРЕКЛЮЧАТЕЛЬ МОДЕЛИ (в начале файла, блок "ПЕРЕКЛЮЧАТЕЛЬ МОДЕЛИ")
  По умолчанию: deepseek/deepseek-chat-v3.1:free  (БЕСПЛАТНО)
  Чтобы включить Claude: раскомментируй строку anthropic/claude-3.5-haiku
    (нужен пополненный баланс OpenRouter). Раскомментируй ОДНУ строку.
  Меняется только модель - остальной код тот же.

ЗАЩИТА ТАБЛИЦ (LLM не сломает)
  - Пишем ТОЛЬКО в лист "Вакансии". Трекер/Дашборд/Справочник не открываются на запись.
  - Только дозапись новых строк. Дедуп по source_id - ничего не перезаписываем.
  - LLM НЕ пишет в таблицу: он возвращает JSON, строку формирует и пишет код по схеме.
  - Кривой ответ LLM -> строка-заглушка "проверь вручную", прогон не падает.

ВЫВОД ПОД ТВОИ СПИСКИ
  Грейд/Формат/Опыт LLM выдаёт из твоего Справочника (Intern/Junior/... ; Офис/
  Удалёнка/Гибрид ; Без опыта/1-3 года/...). Учтены варианты (удаленка/remote/ё)
  -> значения совпадают с выпадающими списками Трекера. Готово к будущему переносу.

КОЛОНКИ ЛИСТА "Вакансии"
  source_id · № · Компания · Должность · Опыт(треб.) · Грейд · Источник · Формат ·
  ЗП вилка · ⚠️ЗП · Локация · Оценка · Вердикт · Опубликовано · Ссылка · Комментарий
  Подсветка: бигтехи (цвет по компании), низкая ЗП <50k (бледно-жёлтый + флаг ⚠️).

ТЕСТ БЕЗ ТРАТ / ПОСТЕПЕННО
  MAX_PER_RUN в настройках: 0 = оценивать всё. Поставь напр. 10, чтобы на первом
  запуске проверить качество на 10 вакансиях, потом вернуть 0.

ПРОМПТ
  Строгий: только факты из текста, нет данных -> "не указано", вердикт сухой,
  вывод строго JSON. Профиль кандидата - в CANDIDATE_PROFILE (правь под себя).

ОГРАНИЧЕНИЯ (честно)
  - Логика (парсинг JSON, нормализация, флаги, цвета, сборка строки) протестирована
    офлайн на мок-данных. Сам вызов LLM и запись в твою таблицу отсюда прогнать
    нельзя - первый реальный запуск твой. Упадёт/выдаст странное - пришли вывод.
  - Бесплатные модели OpenRouter имеют лимиты запросов/мин. Если упрёшься -
    поставь MAX_PER_RUN поменьше или увеличь SLEEP_LLM.
